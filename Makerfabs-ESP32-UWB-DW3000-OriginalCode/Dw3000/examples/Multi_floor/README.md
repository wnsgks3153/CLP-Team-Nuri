# 멀티 플로어 UWB+BLE 위치 측정 시스템

이 프로젝트는 ESP32, DW3000 UWB 모듈, 그리고 BLE를 결합하여 저전력 다층 실내 위치 측정 시스템을 구현합니다. 각 층별 2D 지도에 사용자 위치를 표시하는 데 최적화되어 있습니다.

## 시스템 구성

* **앵커(Anchor)**: 고정된 위치에 설치되는 기준점 장치. BLE 광고를 통해 자신을 알리고, 필요한 경우에만 UWB를 활성화
* **태그(Tag)**: 사용자가 휴대하며 위치를 측정하는 이동 장치. BLE로 주변 앵커를 스캔하고 선택적으로 UWB 통신

## 파일 구조

* `anchor_ble_uwb/anchor_ble_uwb.ino`: BLE와 UWB를 결합한 앵커 장치용 코드
* `tag_ble_uwb/tag_ble_uwb.ino`: BLE와 UWB를 결합한 태그 장치용 코드
* `tag_multi_floor/tag_multi_floor.ino`: UWB만 사용하는 단순화된 태그 코드 (BLE 라이브러리 호환성 문제 발생 시 사용)
* `anchor_multi_floor/anchor_multi_floor.ino`: UWB만 사용하는 단순화된 앵커 코드 (BLE 라이브러리 호환성 문제 발생 시 사용)

## 하드웨어 요구 사항

* ESP32 마이크로컨트롤러 (앵커 및 태그에 사용)
* DW3000 UWB 모듈 (앵커 및 태그에 사용)
* USB 전원 공급 장치 (앵커용)
* 배터리 전원 (태그용)

## 통신 프로토콜

이 시스템은 BLE와 UWB를 결합하여 전력 효율적인 위치 측정을 구현합니다:

1. **BLE 통신**:
   - 앵커는 저전력 BLE 광고를 통해 자신의 ID와 층 정보를 주기적으로 브로드캐스트
   - 태그는 BLE 스캐닝으로 주변 앵커 탐색 및 신호 강도(RSSI) 측정
   - 태그는 BLE 연결을 통해 가까운 앵커의 UWB 모듈만 선택적으로 활성화
   - BLE는 전력 소비가 매우 낮기 때문에 지속적으로 활성화 가능

2. **UWB 통신**:
   - 태그가 활성화한 앵커만 UWB 모듈 켜고 Single-Sided Two-Way Ranging(SS-TWR) 준비
   - SS-TWR 방식으로 정밀한 거리 측정 (센티미터 단위 정확도)
   - 측정 완료 후 앵커는 자동으로 UWB를 비활성화하여 전력 절약

## 설정 방법

### 1. 앵커 설정

각 앵커마다 `anchor_ble_uwb.ino` 파일을 다음과 같이 수정하여 업로드합니다:

```cpp
// !!! 중요: 각 앵커마다 올바른 ID와 층으로 변경 필요 !!!
// 층별 앵커 ID 범위
// 1층 앵커: 0xA001~0xA999 (예: 0xA001, 0xA002, ...)
// 2층 앵커: 0xB001~0xB999 (예: 0xB001, 0xB002, ...)
// 3층 앵커: 0xC001~0xC999 (예: 0xC001, 0xC002, ...)
#define ANCHOR_ID 0xA001  // 앵커 ID (기본값: 1층 첫번째 앵커)
#define ANCHOR_FLOOR 0    // 앵커 층 (0=1층, 1=2층, 2=3층...)

// 앵커 위치 설정 (미터 단위)
// !!! 중요: 각 앵커마다 올바른 좌표로 변경 필요 !!!
#define ANCHOR_X 0.0  // X 좌표
#define ANCHOR_Y 0.0  // Y 좌표
#define ANCHOR_Z 1.5  // Z 좌표 (바닥에서 앵커 높이, 1층의 경우 일반적으로 1.5m)

// BLE 설정
#define BLE_DEVICE_NAME "UWB-Anchor-0xA001" // 앵커 ID를 포함한 이름으로 변경 필요
```

**Z 좌표(높이)의 중요성:**

2D 지도 시각화를 위해서는 X, Y 좌표가 가장 중요하지만, Z 좌표(높이)도 설정해야 합니다. 각 층별로 다음과 같이 표준 Z 값을 사용할 수 있습니다:
- 1층 앵커: Z = 1.5 (바닥에서 1.5m 높이에 설치 가정)
- 2층 앵커: Z = 4.5 (1층 + 층 높이 3m)
- 3층 앵커: Z = 7.5 (2층 + 층 높이 3m)

층 높이가 다른 건물의 경우 실제 설치 높이에 맞게 조정하세요.

### 2. 태그 설정

태그에 `tag_ble_uwb.ino` 파일을 업로드하기 전에 모든 앵커의 정확한 위치와 ID를 반영하도록 다음 코드 부분을 수정하세요:

```cpp
// 앵커 정의
#define NUM_ANCHORS 10 // 앵커 총 개수
AnchorData anchors[NUM_ANCHORS] = {
  // 1층 앵커 (ID는 0xA로 시작)
  {0xA001, {0.0, 0.0, 1.5}, -1.0, false, 0, 0},     // 앵커 1 (1층)
  {0xA002, {5.0, 0.0, 1.5}, -1.0, false, 0, 0},     // 앵커 2 (1층)
  // ... 나머지 앵커들
};
```

각 층마다 최소 3개 이상의 앵커를 설정하는 것이 이상적입니다. 이렇게 하면 동일 층에서 2D 위치 계산의 정확도가 향상됩니다.

### 3. BLE 및 UWB 파라미터 조정

필요에 따라 다음 파라미터를 조정하여 성능과 전력 소비 균형을 맞출 수 있습니다:

```cpp
// 태그 코드
#define BLE_SCAN_TIME 3 // BLE 스캔 시간 (초)
#define BLE_PROXIMITY_RSSI -70 // 가까운 앵커로 판단할 RSSI 임계값
#define MAX_ACTIVE_ANCHORS 5 // 동시에 활성화할 최대 앵커 수
#define ACTIVE_ANCHOR_TIMEOUT_MS 10000 // 앵커 활성화 유지 시간 (10초)

// 앵커 코드
#define UWB_ACTIVE_TIMEOUT_MS 10000 // UWB 활성화 후 자동 비활성화 시간 (10초)
#define BLE_ADVERTISE_INTERVAL 1000 // BLE 광고 간격 (밀리초)
```

## 시스템 작동 원리

### 전력 효율적인 위치 측정 과정

1. **BLE 스캔 & 앵커 발견**: 
   - 태그는 BLE로 주변 앵커를 스캔하고 RSSI 기반으로 가까운 앵커 식별
   - RSSI 값이 `BLE_PROXIMITY_RSSI` 이상인 앵커만 목록에 추가

2. **선택적 UWB 활성화**:
   - RSSI 기준 상위 `MAX_ACTIVE_ANCHORS`개 앵커만 활성화 요청
   - 태그는 BLE를 통해 선택된 앵커의 UWB를 켜도록 요청
   - 앵커는 요청 받으면 UWB를 활성화하고 일정 시간 대기 (`UWB_ACTIVE_TIMEOUT_MS`)

3. **UWB 거리 측정**: 
   - 활성화된 앵커와 태그 간 SS-TWR로 정밀 거리 측정
   - 정확한 타임스탬프 교환으로 센티미터 단위 정밀도 달성
   - 각 앵커에 대한 거리 측정 결과 저장

4. **층별 앵커 선택 및 위치 계산**:
   - 현재 추정 층의 앵커를 우선적으로 사용
   - 2D 삼각측량으로 현재 층 내 위치(X, Y) 계산
   - Z 좌표는 현재 층 번호에 층 높이를 곱한 값으로 설정

5. **층 결정 알고리즘**:
   - 각 층 앵커까지 거리의 역수를 가중치로 활용
   - 층별 평균 가중치 계산 및 최대값 기반 층 결정
   - 히스테리시스 적용으로 안정적인 층 변경

6. **앵커 자동 비활성화**:
   - 앵커는 UWB 활성화 후 일정 시간(`UWB_ACTIVE_TIMEOUT_MS`) 경과 시 자동으로 UWB 비활성화
   - 전력 소비 최소화 (BLE만 활성 상태 유지)

### 2D 삼각측량 방식

코드에서 2D 삼각측량은 단순화된 `calculatePosition()` 함수에서 구현됩니다. 주요 단계는 다음과 같습니다:

1. **2D 좌표 사용**: 각 앵커의 X, Y 좌표만 사용하여 삼변측량을 수행합니다.
2. **동일 층 앵커 활용**: 가장 가까운 앵커들(주로 동일 층)을 사용하여 계산합니다.
3. **삼변측량 계산**:
   - 세 원의 교점 계산: (x-xi)² + (y-yi)² = ri² (각 앵커를 중심으로 하는 원)
   - 원의 방정식을 선형 방정식으로 변환하여 연립방정식 해결
   - 계산된 X, Y 좌표는 태그의 2D 평면상 위치를 나타냄
4. **Z 좌표 설정**: Z 좌표는 현재 층 번호에 층 높이를 곱하고 표준 높이(1.5m)를 더한 값으로 설정

이 방식은 2D 지도를 층별로 표시하는 시각화에 최적화되어 있으며, 계산이 단순하고 CPU 자원 사용을 줄입니다.

## 시스템 설치

1. 각 층별로 최소 3개 이상의 앵커를 설치합니다.
2. 앵커 위치는 서로 같은 선상에 위치하지 않도록 삼각형 배치를 권장합니다.
3. 각 앵커의 정확한 X, Y 좌표를 실측하여 기록합니다.
4. 앵커 ID는 층별로 다른 범위를 사용합니다 (1층: 0xA***, 2층: 0xB***, 3층: 0xC***).
5. 모든 앵커에 전원을 연결합니다.
6. 태그 장치를 프로그래밍하고 전원을 연결합니다.

## 실행 방법

1. 모든 앵커 전원을 켭니다.
2. 태그를 켜고 시리얼 모니터로 연결합니다 (115200 baud).
3. 태그는 자동으로 BLE 스캔으로 주변 앵커를 찾고, 가까운 앵커의 UWB를 활성화합니다.
4. 위치 정보는 시리얼 포트를 통해 `<POS>{...}</POS>` 형식으로 출력됩니다.

## 데이터 형식

태그는 다음과 같은 JSON 형식으로 위치 데이터를 출력합니다:

```
<POS>{"x":3.45,"y":2.71,"z":1.5,"floor":1,"valid":true}</POS>
```

* `x`, `y`: 2D 평면상의 미터 단위 좌표
* `z`: 층 높이 기반 Z 좌표 (미터)
* `floor`: 현재 층 (1=1층, 2=2층, 3=3층)
* `valid`: 위치 계산 성공 여부

## 전력 소비 최적화

이 시스템은 다음과 같은 전력 최적화 전략을 적용합니다:

1. **선택적 UWB 활성화**: 
   - UWB는 전력 소비가 큰 모듈이므로 필요할 때만 활성화
   - BLE 스캔으로 가까운 앵커만 선택적으로 UWB 활성화

2. **자동 비활성화 타이머**: 
   - 앵커는 UWB 활성화 후 일정 시간(`UWB_ACTIVE_TIMEOUT_MS`) 후 자동으로 UWB 비활성화
   - 통신이 없는 대기 상태에서 불필요한 전력 소비 방지

3. **앵커 수 제한**: 
   - 태그는 최대 `MAX_ACTIVE_ANCHORS`개 앵커만 활성화
   - 거리에 기반한 선택으로 측위에 충분한 앵커만 활성화

4. **BLE 광고 간격 조정**: 
   - 앵커의 BLE 광고 간격(`BLE_ADVERTISE_INTERVAL`)을 조절하여 전력 소비와 응답성 사이 균형 조정
   - 더 긴 간격은 전력 소비 감소 (대신 태그의 앵커 발견 시간 증가)

5. **층별 앵커 그룹화**: 
   - 층별 ID 체계로 태그가 현재 층 앵커만 우선 활성화
   - 다른 층의 앵커는 보조적으로만 사용되어 거리가 먼 앵커 활성화 최소화

## 주의 사항

1. **BLE 라이브러리 호환성**: 
   - ESP32 버전에 따라 BLE 라이브러리 호환성 문제가 발생할 수 있음
   - 호환성 문제 발생 시 `tag_multi_floor.ino` 및 `anchor_multi_floor.ino` 사용 권장 (UWB만 사용)

2. **앵커 배치**: 
   - 각 층마다 최소 3개 이상의 앵커 설치 권장
   - 삼각형 형태로 배치하여 위치 정확도 향상

3. **통신 환경**:
   - UWB 신호는 금속 장애물에 의해 차단될 수 있음
   - BLE 신호는 UWB보다 장애물에 더 민감하므로 BLE 광고가 도달 가능한 위치에 앵커 배치

4. **전력 공급**:
   - 앵커는 안정적인 전원 공급 필요
   - 태그는 배터리 작동을 위해 저전력 소비 중요

## 문제 해결

* **BLE 스캔 실패**: ESP32 버전이 사용 중인 BLE 라이브러리와 호환되는지 확인하세요.
* **앵커 발견 안됨**: BLE_PROXIMITY_RSSI 값을 낮추어(예: -80) 더 멀리 있는 앵커도 감지하도록 조정하세요.
* **UWB 활성화 실패**: 앵커와 태그 간 BLE 통신이 정상적으로 이루어지는지 확인하세요.
* **위치 계산 실패**: 최소 3개 이상의 앵커와 통신이 가능한지 확인하세요.
* **층 결정 오류**: 각 층에 충분한 수의 앵커가 설치되었는지 확인하세요.
* **앵커 배터리 소모 빠름**: BLE_ADVERTISE_INTERVAL 값을 늘려 광고 빈도를 줄이세요.
* **태그 배터리 소모 빠름**: BLE_SCAN_TIME, CYCLE_DELAY_MS 값을 늘려 스캔 빈도를 줄이세요.
